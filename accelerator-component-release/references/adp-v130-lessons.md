# ADP v1.3.0 Lessons

Use this reference when driving future accelerator component releases after the completed `hami-ascend-device-plugin v1.3.0` release.

## Reusable Rules

- Start from source and branch. Do not require the maintainer to prepare a package first.
- Treat `profile + evidence -> facts -> gaps/actions -> action result -> facts` as the release loop.
- Only create the formal tag after RC function tests, RC package/image precheck, independent CVE scan, and residual-risk approval.
- The formal tag must point to the tested commit and must be proven on the remote with peeled commit evidence.
- Build the formal package from the formal tag, not from the release branch.
- Run release-grade CVE scan after RC rollout, function/e2e, and package content validation. Build-time image scan is not a hard release gate.
- Preserve RC history. Older RCs explain gap closure; only one candidate is current.
- Use a `-test` material directory for source-first automation trials, then promote to `docs/releases/<component>-<version>` after gap closure.

## HAMi Ascend Device Plugin Specifics

- For operator components, `CSV Succeeded` or CR existence is not enough. Verify CR `Deployed=True`, target DaemonSet ownership, Running Pod, and candidate image.
- HAMi ADP and Huawei original `ascend-device-plugin` must not both own the same 310P active path during standard release tests.
- If the vendor plugin is moved away from the test node, restart the HAMi ADP Pod and wait until `allocatable.huawei.com/Ascend310P > 0` before running hard/soft e2e.
- Use the environment window script when available:

```bash
hack/hami-ascend-device-plugin-release-env-window.sh <kubeconfig> -- \
  hack/hami-ascend-device-plugin-release-test.sh <kubeconfig>
```

## Artifacts Repo

- For components that build their own operator package, `aml/artifacts` is registration-only, not the package builder.
- AC upload requires a packaged plugin/install artifact URL, but `artifacts-plugin` is only a fallback build path. Skip `artifacts-plugin` when the component pipeline already produced the formal plugin package; run it only for components that produced chart/image metadata but no plugin package.
- Still require both:
  - `master`: latest component registration
  - `<component>-<version>`: historical release branch registration
- Align the artifacts component directory with the package-minio package prefix. For ADP v1.3.0 the AC upload directory was `hami-ascend-device-plugin-operator`.

## AC Upload

- Use Edge BuildRun `artifacts-upload-ac`, not `artifacts-update`.
- Upload is mutating and must be the last blocking gap except `GAP-AC-LISTING`.
- Confirm these before upload:
  - branch: `<component>-<version>` in artifacts repo
  - `upload_artifacts`
  - `acp_version`
  - `ac_env`
  - `upload_versions`
  - `auto_commit`
  - `reuse_version_meta`
  - `upload_no_pack`
  - `overwrite_s3`
  - `image`
- Reject unknown keys, missing keys, or renamed keys.
- After upload, validate with read-only AC listing when possible. If one platform listing API fails, closure needs explicit maintainer acceptance plus upload logs proving success.

## Formal Package Rebuild

If package-minio already has a stale same-version package:

1. Read and save current package/checksum evidence.
2. Do not delete the package body by default.
3. With maintainer confirmation, empty the `.tgz.checksum` object to force repack.
4. Rebuild from the formal tag.
5. Download and unpack the formal package.
6. Verify sha256/md5, relatedImages, image tags, and image labels point to the formal tag commit.

This is an operational remedy. Do not put the checksum-emptying step into customer-facing product docs.

## Product Docs

Release completion includes product docs. For ADP v1.3.0:

- Update English docs only when Chinese is generated by the docs pipeline.
- Use product name `Alauda Build of HAMi Ascend Device Plugin`.
- Do not include internal AC/cloudmanage management URLs.
- Document native capability, not only tested scope, unless explicitly writing a test report.
- Keep internal pipeline/S3/temporary environment details out of product docs.
